Deploying Shrink Ray

Before you continue with these instructions you need to create your Digital Ocean droplet and set up your DNS records for your domain name.

Droplet Setup Script

When creating your droplet, paste the following into the User Data field under Advanced Options. It will automatically run on first boot and handle software installation and firewall configuration for you.

#!/bin/bash

export DEBIAN_FRONTEND=noninteractive
APT_OPTS='-o Dpkg::Options::=--force-confold -o Dpkg::Options::=--force-confdef'

# Install Caddy
apt-get install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list
apt-get update
apt-get $APT_OPTS -y upgrade
apt-get install -y caddy

# Clear the default Caddyfile
>/etc/caddy/Caddyfile

# Install Node.js 24
curl -fsSL https://deb.nodesource.com/setup_24.x | bash -
apt-get install -y nodejs

# Install PM2
npm install pm2 -g

# Configure firewall
ufw allow OpenSSH
ufw allow 80
ufw allow 443
ufw allow 443/udp
ufw --force enable

Once your droplet finishes booting (give it a few minutes), SSH in and verify the installation:

First this command so you can wait until the startup script is finished running before you try any other commands:

sudo cloud-init status --wait

It will output ....... until you’ll finally see status: done. For example this was my output (it can take a while for the startup script to finish running):

root@webDevSpring26:~# sudo cloud-init status --wait
....................................................status: done

When you see the output status: done then you can run:

node --version
caddy version
sudo ufw status

Your output should be something like:

root@shrinkRayTest:~# node --version
v24.15.0
root@shrinkRayTest:~# caddy version
v2.11.2 h1:iOlpsSiSKqEW+SIXrcZsZ/NO74SzB/ycqqvAIEfIm64=
root@shrinkRayTest:~# sudo ufw status
Status: active

80                         ALLOW       Anywhere

443/udp (v6)               ALLOW       Anywhere (v6)

Stop here if you don't have a domain name! You need to set up your A records before continuing.

Clone Your Project Repository

Copy your project repository from github to your server using the git clone command. For this example you’ll clone my project repo but you should replace it with your own project later.

# Clone project
git clone https://github.com/csaldivar-astate/shrinkRay.git /root/shrinkRay

Create Your Environment File

cd into the project directory:

cd ~/shrinkRay

Since you are running in a new environment you need to create your .env file.

Generate a random secret:

openssl rand -hex 16

Then create the file:

nano .env

Add your environment variables:

PORT="8000"
COOKIE_SECRET="PUT_YOUR_RANDOM_HEX_STRING_HERE"
DATABASE_NAME="whateverYouCallYourDatabase.sqlite"
NODE_ENV="production"

Save and quit nano:

  • ctrl + x
  • Type the letter y
  • enter
Remember you should never put your .env file in source control. The COOKIE_SECRET should be the random hex string you generated above.

Install Dependencies and Build

npm install
npm run build
This compiles your project with a higher level of optimization than npm run compile. We only use this when building the application for production.

Configure Caddy as a Reverse Proxy

Caddy’s configuration lives in a file called a Caddyfile. Unlike NGINX, there is no separate TLS setup step: Caddy automatically obtains and renews a free certificate from Let’s Encrypt the first time a request comes in for your domain.

Open the default Caddyfile for editing:

sudo nano /etc/caddy/Caddyfile

All of these examples use redWolves.dev as an example but it should be replaced with YOUR domain name.

Replace the file’s entire contents with the following. Replace redWolves.dev with your domain name and 8000 with whatever port you set in your .env.

redWolves.dev, www.redWolves.dev {
    reverse_proxy localhost:8000
}

Save and quit:

  • ctrl + x
  • Type the letter y
  • enter

Then reload Caddy with this command:

sudo systemctl reload caddy

Run the Server with PM2

Start your application server with PM2 so it stays running after you disconnect your SSH session:

pm2 start dist/index.js

Check That It Works

Visit your domain name in a browser. The URL bar should show a secure HTTPS connection. Caddy provisions the certificate on the first request, so give it a few seconds.

Your application is live!
